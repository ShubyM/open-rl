Components

What each piece owns, and why it exists as its own piece.

open-rl gateway

Presents the tinker API on :9003. The training loop is plain SDK code against it and never learns whether the trainer is in-process or a separate job, or whether sampling is one server or seven. Changing that shape is config, not code.

vLLM sampler

Serves the Qwen3.5-9B policy and holds KV cache for long multi-turn episodes. Loads a new LoRA adapter at runtime between steps, so it never restarts mid-run.

LoRA trainer

Runs forward/backward and the optimizer step on its own cards. Split from the sampler because gradients and KV cache would otherwise fight for the same memory.

Task sandbox

A rootless podman container per episode, holding the matter's documents and the shell and file tools the model works with. Torn down when the episode ends.

GLM-5.2 judge

A second large model, on its own machine because it is never trained — colocating it would cost the trainer half its cards to serve inference. Self-hosting it also means a batch's episodes grade concurrently instead of queueing behind an API rate limit.

Checkpoints

Two artifacts per save with different jobs — the handoff to the sampler, and the thing that resumes a run. Detailed below.

Checkpointing

Every optimizer step writes an adapter; every fifth also writes full training state.

Adapter snapshot

~350 MB
every step

LoRA weights only. Written under a fresh immutable directory each time, so rollouts still in flight keep reading a complete one.

  • Feeds the sampler — this is the hot-load.
  • Warm-starts a new run — weights carry over, optimizer starts fresh. What you want when the objective changes, like SFT → RL.
  • Offline eval — point it at any past step.
/tmp/open-rl/peft/<model-id>/<label>/

Full checkpoint

~1 GB
every 5 steps

The adapter plus optimizer.pt — the Adam moments the snapshot leaves behind.

  • Resumes a run exactly, momentum intact, rather than re-warming from scratch.
  • The only artifact that can do that, which is why the cadence is worth its disk.
/tmp/open-rl/checkpoints/<model-id>/weights/<label>/
Both live on local disk, on spot instances. Losing a machine loses every checkpoint on it — anything worth keeping is copied off to HF Hub or GCS.
